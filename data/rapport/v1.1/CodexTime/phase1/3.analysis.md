## 1. Objectif précis

Créer une brique technique dédiée à l’exécution de Codex CLI.

Cette brique doit permettre de :

* recevoir une requête d’exécution Codex
* exécuter la commande
* capturer le résultat
* remonter un résultat structuré exploitable par la suite

Important :
cette brique ne pilote pas le workflow.
Elle n’interprète pas les résultats.
Elle ne prend aucune décision métier.
Elle n’oriente aucune suite d’action.

Elle exécute uniquement un appel Codex et retourne un résultat technique structuré.

---

## 2. Éléments attendus

Créer au minimum :

## 3. `CodexExecutionRequest`

Objet simple représentant une demande d’exécution Codex.

Il doit permettre au minimum de transporter :

* le prompt à exécuter
* éventuellement le répertoire de travail
* éventuellement un timeout
* éventuellement des paramètres simples utiles à l’exécution

Contraintes :

* rester sobre
* pas de champ métier de workflow
* pas de notion de lot, d’étape, de décision humaine ou de review
* pas de logique de construction compliquée

Le prompt doit être obligatoire.

Le répertoire de travail peut être optionnel si cela reste cohérent avec le projet.

---

## 4. `CodexExecutionResult`

Objet simple représentant le résultat technique d’une exécution Codex.

Il doit permettre au minimum de remonter :

* la commande exécutée ou sa représentation utile
* le code retour
* stdout
* stderr
* indicateur de succès/échec
* éventuellement indicateur de timeout si utile
* éventuellement durée d’exécution si simple à récupérer

Contraintes :

* objet purement technique
* pas d’interprétation métier
* pas de logique de parsing intelligent des résultats
* pas de notion de validation fonctionnelle

Important :
le résultat doit être exploitable plus tard par d’autres briques, mais ici il reste neutre et bas niveau.

---

## 5. `CodexWorkflowClient`

Créer une brique technique dédiée à l’appel Codex.

Responsabilités attendues :

* recevoir un `CodexExecutionRequest`
* exécuter Codex CLI
* produire un `CodexExecutionResult`
* gérer proprement :

    * timeout
    * erreurs système simples
    * stdout / stderr
    * code retour

Contraintes majeures :

* pas de logique d’orchestration
* pas de lecture de roadmap
* pas de génération d’artefacts métier
* pas de lien avec `WorkflowStep`
* pas de lien Telegram
* pas de lien Maven/build
* pas de logique de retry ici
* pas de décision sur “on continue ou non”

Cette classe doit rester un client technique.
