## 1. Objectif précis

Créer un orchestrator minimal capable d’exécuter UNE `WorkflowStep` à partir d’un `WorkflowExecutionContext`, puis d’interpréter minimalement le `WorkflowStepResult`.

---

## 2. Classe à implémenter

Créer :

* `WorkflowOrchestrator`

Et les tests associés :

* `WorkflowOrchestratorTest`

Important :
je veux une classe concrète simple.
Ne pas transformer cette étape en intégration Spring avancée.
Tu peux laisser l’annotation `@Service` de côté pour ce lot si elle n’est pas nécessaire.

---

## 3. Comportement attendu

Introduire une méthode publique simple du type :

* `executeSingleStep(WorkflowExecutionContext context, WorkflowStep step)`

Cette méthode doit :

1. valider que `context` n’est pas nul
2. valider que `step` n’est pas nul
3. appeler `step.execute(context)` exactement une fois
4. valider que le résultat n’est pas nul
5. interpréter la décision

Comportement minimal sur la décision :

* `CONTINUE` → retourner le résultat
* `WAIT_HUMAN` → retourner le résultat
* `STOP_FAILURE` → retourner le résultat
* toute autre décision → erreur explicite indiquant que cette décision n’est pas supportée à ce stade

---

## 4. Contraintes de conception

Je veux un orchestrator :

* minimal
* lisible
* strict
* sans intelligence cachée

Je ne veux pas :

* de boucle
* de multi-step
* de state machine
* de pipeline
* de router
* de transition engine
* de plugin system
* de logique de retry
* de mise à jour complexe du runtime

---

Pour cette étape :

L’orchestrator doit uniquement :
