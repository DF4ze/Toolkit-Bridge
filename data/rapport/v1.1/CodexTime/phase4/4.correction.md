# Phase 4 - Etape 4 - Prompt de correction

Correction de robustesse demandee.

Objectif:
- ne pas faire dependre le succes du workflow de l'ecriture du summary
- restaurer une reprise manuelle robuste
- corriger la coherence de `correctionTriggered`

Contraintes:
- ne pas modifier l'orchestrator
- ne pas introduire de nouvelle classe
- ne pas ajouter de couche d'architecture
- rester minimal

Actions demandees:
1. Dans `AnalysisReviewWorkflowRunner`, encapsuler la generation du summary dans un try/catch et ne jamais faire echouer le run metier pour une raison documentaire.
2. Rendre la generation du summary conditionnelle (si variables de reporting presentes), sinon ne rien faire.
3. Dans `CorrectionStep.stopFailure(...)`, mettre `correctionTriggered=false` pour les echecs precoces.
4. Ajouter les tests:
   - summary KO -> run OK
   - variables absentes -> run OK
   - correction failure -> correctionTriggered coherent

Livrable:
- corrections appliquees
- tests completes
- build vert
