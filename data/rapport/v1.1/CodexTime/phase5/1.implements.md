N'oublie pas d'enregistrer le prompt de demande d'implémentation dans 1.implements.md.

Tu peux passer à l’implémentation.

Ton analyse est validée avec un ajustement important :
la façade applicative est optionnelle et ne doit pas être introduite si elle n’apporte pas de valeur immédiate.

---

## Objectif

Rendre le workflow appelable depuis l’extérieur en s’appuyant directement sur le runner existant.

---

## À modifier / créer

* ajouter un point d’entrée simple (classe Java ou main)
* utiliser directement `AnalysisReviewWorkflowRunner`

⚠️ Ne pas modifier :

* `WorkflowOrchestrator`
* les steps
* `WorkflowStepResult`

---

## 1. Stratégie

### Par défaut

Utiliser directement :

```text
AnalysisReviewWorkflowRunner
```

---

### Façade (optionnelle)

Créer seulement si nécessaire :

```text
AnalysisReviewWorkflowCommandService
```

⚠️ uniquement comme délégation simple
⚠️ sans logique métier

---

## 2. Point d’entrée concret

Créer un point d’entrée simple :

Exemple :

```text
Main class / CLI simple
```

Capable de :

* RUN complet
* RESUME correction

---

## 3. RUN

Appeler :

```text
runner.runAnalysisReviewWithOptionalCorrection(context)
```

---

## 4. RESUME

Appeler :

```text
runner.runCorrectionAfterReview(context)
```

---

## 5. Contrat de sortie

Retourner :

* decision
* message
* finalDecision
* nextAction
* workflowSummaryPath (si présent)

⚠️ ne pas créer de DTO complexe

---

## 6. Contexte

Construire un `WorkflowExecutionContext` simple avec :

* reportRootDirectory
* reportVersion
* reportPhase
* stepNumber
* analysisSourcePath (RUN uniquement)

---

## 7. Contraintes

* pas de Spring lourd
* pas de moteur de commande
* pas de refactor global
* pas de nouvelle architecture
* pas de duplication

---

## 8. Tests

* RUN via point d’entrée
* RESUME via point d’entrée
* validation des résultats
