# PROMPT — Implémentation Phase 5 Étape 5a — Documentation CLI externe

## Contexte

Tu interviens sur `Toolkit-Bridge`, Phase 5 Étape 5.

Le rapport d'analyse a conclu que le système est partiellement prêt pour Telegram, mais qu'il manque une documentation externe claire du contrat CLI.

## Objectif

Créer une documentation Markdown décrivant le contrat externe de la CLI `AnalysisReviewWorkflowCli`.

Cette documentation doit permettre à un futur bot Telegram, script externe ou outil local de comprendre comment appeler le workflow sans lire le code Java.

## Travail demandé

Créer le fichier :

`data/rapport/v1.1/Phase5/etape5/cli-reference.md`

Il doit documenter :

* le rôle de `AnalysisReviewWorkflowCli`
* les modes disponibles :

  * `RUN`
  * `RESUME`
* les paramètres obligatoires
* les paramètres optionnels
* les exemples d'appel
* les codes de sortie :

  * `0`
  * `1`
  * `2`
* le format stdout `key=value`
* les clés actuellement attendues :

  * `finalDecision`
  * `message`
  * `nextAction`
  * `waitReason`
  * `workflowSummaryPath`
  * `correctionTriggered`
* le fait que `workflowSummaryPath` peut être absent si le contexte de summary est incomplet
* le fait que les chemins retournés sont des chemins locaux
* les limites connues pour une future intégration Telegram :

  * pas de rendu Telegram dédié
  * pas de gestion de session RUN → RESUME
  * longueur de message non bornée
  * décisions `FINISH` et `RETRY_CORRECTION` potentiellement mappées en `UNKNOWN` côté simulateur

## Contraintes strictes

* Ne modifie aucun fichier Java.
* Ne crée aucun composant Telegram.
* Ne crée aucun renderer.
* Ne modifie pas le runtime.
* Ne change pas le contrat CLI.
* Ne fais qu'ajouter la documentation Markdown.
* Reste factuel : ne documente que le comportement existant.
* Si un point n'est pas certain après lecture du code, indique-le explicitement dans une section "Points à vérifier".
