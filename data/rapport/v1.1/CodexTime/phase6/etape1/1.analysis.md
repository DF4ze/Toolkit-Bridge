# PROMPT — Analyse Phase 6 Étape 1 — Introduire une validation locale minimale

## Contexte

Tu interviens sur le projet Java Spring `Toolkit-Bridge`.

Nous sommes en :

`v1.1 / Phase 6 / Étape 1`

La Phase 6 vise à rendre le workflow Codex techniquement fiable.

Aujourd'hui, le workflow est appelable depuis l'extérieur et pilotable humainement, mais il ne valide pas encore localement que le code compile ou que les tests passent.

## Objectif de l'étape

Analyser comment introduire une première brique de validation locale minimale.

Cette brique doit permettre au workflow d'exécuter une commande locale simple, typiquement Maven, et de récupérer :

* le code retour
* stdout
* stderr
* durée d'exécution
* succès / échec
* erreur système éventuelle
* timeout éventuel

## Important

Cette étape est uniquement une analyse.

Tu ne dois rien implémenter.

## Travail demandé

Analyse le dépôt actuel et identifie :

1. Les classes/fichiers concernés par l'ajout d'une validation locale.
2. Où placer proprement le futur service `WorkflowValidationService`.
3. Quels objets métier minimaux introduire.
4. Comment exécuter une commande locale sans créer un moteur shell générique dangereux.
5. Comment gérer : timeout, code retour non zéro, exception système, stdout/stderr volumineux.
6. Comment tester ce service sans lancer réellement Maven dans tous les tests.
7. Quels risques d'architecture ou de sécurité sont à anticiper.
8. Comment préparer l'étape suivante qui lancera `mvn clean compile -DskipTests`.

## Contraintes strictes

* Ne pas modifier le runtime workflow existant.
* Ne pas brancher encore la validation dans le runner.
* Ne pas lancer Maven automatiquement à cette étape.
* Ne pas créer de moteur shell générique.
* Ne pas ajouter Telegram.
* Ne pas ajouter de persistance.
* Ne pas modifier le contrat CLI.
* Ne pas sur-architecturer.
