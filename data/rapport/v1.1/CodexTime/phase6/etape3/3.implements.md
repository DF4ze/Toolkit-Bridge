## Contexte

Le workflow inclut maintenant :

* analyse Codex
* review Codex
* correction Codex
* validation Maven

Actuellement :

→ erreur build = STOP_FAILURE

Objectif :

👉 ajouter une boucle d'auto-correction contrôlée

---

## Travail demandé

---

## 1. Modifier `MavenValidationStep`

### Nouveau comportement

| Cas                    | Décision         |
| ---------------------- | ---------------- |
| SUCCESS                | CONTINUE         |
| FAILURE + retry < max  | RETRY_CORRECTION |
| FAILURE + retry >= max | STOP_FAILURE     |
| TIMEOUT                | STOP_FAILURE     |
| SYSTEM_ERROR           | STOP_FAILURE     |

---

### Variables à gérer

Dans `context.variables()` :

* `buildErrorRetryCount` (default 0)
* `buildErrorRetryMax` (default 2)

---

### Incrément

Sur FAILURE :

```java
retryCount++
```

---

## 2. Créer `BuildErrorCorrectionStep`

### Objectif

Relancer Codex avec le contexte d'erreur Maven

---

### Input

* extrait erreur build
* path artifact build
* contexte existant

---

### Output

* `WorkflowStepResult`
* decision = CONTINUE

---

### Important

* ne pas parser Maven de manière complexe
* rester simple :

  * prendre stderr tronqué
  * ou lire artifact

---

## 3. Modifier `AnalysisReviewWorkflowRunner`

Créer :

```java
runWithValidationAndRetry(context)
```

---

### Logique

```text
loop:
  runWithValidation()

  if CONTINUE → STOP (success)

  if STOP_FAILURE → STOP (failure)

  if RETRY_CORRECTION:
      run BuildErrorCorrectionStep
      continue loop
```

---

### Conditions d'arrêt

* retry >= max
* ou STOP_FAILURE
* ou SUCCESS

---

## 4. Tests

Ajouter :

* retry 1 fois → success
* retry max atteint → STOP_FAILURE
* TIMEOUT → pas de retry
* SYSTEM_ERROR → pas de retry
