# PROMPT - Correction Phase 6 Etape 4 - WAIT_HUMAN manquant

## Contexte

L'implementation actuelle introduit `WAIT_HUMAN` pour les echecs persistants.

Mais un probleme existe :

- le cas reel de retry max atteint est intercepte par la garde du runner
- et ne passe pas par la conversion `WAIT_HUMAN`

## Objectif

Corriger le runner pour que le cas reel de retry max atteint declenche `WAIT_HUMAN`.

## Corrections a appliquer

### 1. Corriger la garde `retryCount >= retryMax`

Dans `runWithValidationAndRetry` :

```text
si retryCount >= retryMax
  ET buildStatus == FAILURE
  ET correctionTriggered == true
-> WAIT_HUMAN

sinon -> STOP_FAILURE
```

### 2. Forcer `correctionTriggered=true` cote runner

Apres succes de `BuildErrorCorrectionStep`, ajouter explicitement :

```text
correctionTriggered = true
```

dans le contexte courant.

### 3. Ajouter test realiste

```text
RETRY_CORRECTION (1/2)
-> correction
-> RETRY_CORRECTION (2/2)
-> WAIT_HUMAN
```

Ce test doit utiliser le comportement reel de `MavenValidationStep`.

### 4. Securiser `hasBuildContext`

Rendre la detection plus stricte :

- verifier `buildStatus == FAILURE`
- ou presence de `waitReason` specifique build

## Contraintes strictes

- ne pas modifier orchestrateur
- ne pas modifier steps
- ne pas ajouter logique complexe
- ne pas parser Maven
