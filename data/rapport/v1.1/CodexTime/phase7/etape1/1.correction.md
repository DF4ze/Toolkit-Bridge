# PROMPT — Correction Phase 7 Étape 1 — Controller Telegram Workflow

À enregistrer :

`data/rapport/v1.1/CodexTime/Phase7/etape1/1.correction.md`

## Objectif

Corriger l’implémentation du controller Telegram workflow minimal pour respecter le fonctionnement réel du module `TelegramBots`.

## Corrections à appliquer

### 1. Revenir sur `DefaultController`

Annuler toutes les modifications faites dans :

`DefaultController.java`

et dans ses tests associés.

Le controller runtime agent ne doit pas connaître `/workflow`.

### 2. Corriger `WorkflowTelegramController`

Le controller doit être annoté avec :

`@TelegramController(name = "Cortex")`

Car le bot `Cortex` est déjà déclaré dans la configuration YAML.

### 3. Ajouter la commande via `@Command`

Dans `WorkflowTelegramController`, ajouter uniquement une méthode :

`@Command(value = "/workflow", description = "Workflow interface")`

Elle retourne :

`Workflow Telegram interface is available but not connected yet.`

### 4. Supprimer toute logique inutile

Supprimer si présent :

* gestion manuelle de botId
* `@Chat`
* parsing manuel de commande
* fallback sur botId null
* logique d’ignorance côté controller existant

Le routage par bot doit être porté par `@TelegramController(name = "Cortex")`.

### 5. Tests

Adapter les tests pour vérifier :

* `/workflow` retourne le message attendu
* le controller est dédié à `Cortex`
* aucune modification de `DefaultController`
* aucun appel CLI/workflow/runner

## Contraintes strictes

* Ne pas gérer `/start`
* Ne pas gérer `/help`
* Ne pas gérer `/ping`
* Ne pas modifier `/whoiam`
* Ne pas brancher le workflow
* Ne pas modifier le runner
* Ne pas modifier la CLI
* Ne pas modifier l’orchestrateur
