# PROMPT — Implémentation Phase 7 Étape 1 — Controller Telegram Workflow minimal

À enregistrer :

`data/rapport/v1.1/CodexTime/Phase7/etape1/1.implements.md`

## Contexte

Le projet possède déjà une intégration Telegram via `telegram-bots-mvc`.

Il existe déjà des commandes intégrées au module Telegram, notamment `/help` et `/whoiam`.

Le `/start` est également traité par le mécanisme d’authentification du module Telegram :

* utilisateur non identifié → rejet avant controller
* utilisateur identifié → controller éventuellement appelé

Donc cette étape ne doit pas ajouter de commande `/start`, `/help` ou `/ping`.

## Objectif

Créer une première couche Telegram dédiée au workflow Codex, sans encore brancher le workflow.

L’objectif est uniquement de préparer l’isolation du futur canal Telegram workflow.

## Travail demandé

Créer un controller Telegram dédié au workflow, par exemple :

`WorkflowTelegramController`

Dans un package dédié, par exemple :

`fr.ses10doigts.toolkitbridge.controler.telegram.workflow`

Le controller doit :

* être isolé du `DefaultController` existant
* ne pas appeler le runner
* ne pas appeler la CLI
* ne pas lire `workflow-summary.md`
* ne pas gérer `WAIT_HUMAN`
* ne pas ajouter `/start`
* ne pas ajouter `/help`
* ne pas ajouter `/ping`
* ne pas modifier `/whoiam`

## Commande minimale

Ajouter uniquement une commande spécifique au workflow, par exemple :

`/workflow`

Réponse attendue :

`Workflow Telegram interface is available but not connected yet.`

## Isolation

Le controller doit être prévu pour ne répondre qu’au botId workflow si l’information est disponible dans `TelegramUpdateContext`.

Si le botId ne correspond pas, il doit ignorer proprement le message.

## Tests attendus

Ajouter des tests unitaires simples :

* `/workflow` retourne le message attendu
* commande inconnue ignorée
* botId non correspondant ignoré si applicable
* aucun appel workflow/CLI n’est fait

## Contraintes strictes

* Ne pas gérer `/start`
* Ne pas gérer `/help`
* Ne pas gérer `/ping`
* Ne pas modifier `/whoiam`
* Ne pas brancher le workflow
* Ne pas modifier le runner
* Ne pas modifier la CLI
* Ne pas modifier l’orchestrateur
* Ne pas ajouter de persistance
* Ne pas gérer les secrets maintenant
