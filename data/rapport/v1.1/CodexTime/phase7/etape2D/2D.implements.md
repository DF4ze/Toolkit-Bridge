# PROMPT — Implémentation Phase 7 Étape 2D — Affichage du workflow-summary

## Contexte

Le workflow génère un fichier :

```text
workflow-summary.md
```

Ce fichier est :
* écrit par le runner (intouchable)
* stocké sur disque
* référencé dans `WorkflowTelegramSession.lastSummaryPath`

Le système Telegram dispose déjà :
* d’un `WorkflowTelegramSessionStore`
* d’un `WorkflowTelegramController`
* d’un `Workspace` / tool sécurisé pour accéder au filesystem

## Objectif

Permettre à l’utilisateur Telegram de consulter le summary via :

```text
/workflow_summary
```

Avec un affichage :
* lisible
* robuste
* sécurisé
* compatible avec la limite Telegram (~4096 chars)

## Travail demandé

## 1. Ajouter la commande Telegram

Dans :

```java
WorkflowTelegramController
```

Ajouter :

```java
@Command("/workflow_summary")
```

Le controller :
* récupère le `chatId`
* délègue à un service
* retourne le résultat

## 2. Créer un service dédié

Créer :

```text
WorkflowTelegramSummaryService
```

Responsabilités :
* récupérer la session
* lire le summary via le workspace sécurisé
* gérer la taille
* construire les messages

## 3. Lecture du fichier (IMPORTANT)

👉 Interdiction :

```text
Files.readString(...)
```

👉 Obligatoire :
* utiliser le tool / service workspace existant
* ne jamais accéder directement au filesystem
* ne pas réimplémenter la sécurité de path

## 4. Gestion des cas

### Aucun summary

```text
❌ Aucun summary disponible
Lance /workflow_run d’abord
```

### Fichier absent

```text
❌ Summary introuvable sur disque
```

### Fichier vide

```text
⚠️ Summary vide
```

## 5. Gestion taille (TRÈS IMPORTANT)

Constante :

```text
MAX_TELEGRAM_TEXT = 3800
MAX_CHUNKS = 2
```

### Cas 1 — contenu court

```text
length <= MAX_TELEGRAM_TEXT
```

👉 envoyer 1 message

### Cas 2 — contenu moyen

```text
length > MAX_TELEGRAM_TEXT
mais <= 2 chunks
```

👉 split en 2 messages max

Format :

```text
Workflow summary (1/2)
...
Workflow summary (2/2)
...
```

### Cas 3 — contenu long

```text
> 2 chunks
```

👉 NE PAS spam

👉 faire :
1. envoyer message court :

```text
⚠️ Summary trop long
Envoi du fichier complet
```

2. envoyer le fichier via le workspace/tool (document Telegram)

## 6. Stratégie de découpage

* découper de préférence sur `\n`
* fallback si pas possible : split brut
* ne jamais dépasser `MAX_TELEGRAM_TEXT`

## 7. Format du message

👉 Texte brut uniquement
* pas de Markdown
* pas de HTML
* pas de parsing du contenu

## 8. Sécurité

* utiliser uniquement le path provenant de la session
* ne pas recalculer de path
* ne pas accéder directement au filesystem
* déléguer toute validation au workspace/tool

## 9. Tests

Ajouter tests unitaires :

### Lecture
* summary absent → message erreur
* fichier absent → erreur
* fichier vide → message warning

### Taille
* contenu court → 1 message
* contenu moyen → 2 messages
* contenu long → document

### Split
* découpage correct
* respect des limites

### Sécurité
* aucun accès direct `Files.*`
* mock du workspace/tool

## 10. Contraintes strictes

* ne pas modifier runner
* ne pas modifier CLI
* ne pas parser le summary
* ne pas ajouter logique métier
* ne pas stocker le contenu en mémoire long terme
* rester simple et testable
