# PROMPT — Analyse Phase 7 Étape 5 — Améliorer l’UX Telegram

## Contexte

Tu interviens sur le projet `Toolkit-Bridge`.

La Phase 7 vise l’intégration Telegram du workflow Codex.

Les étapes déjà réalisées permettent maintenant :

* `/workflow_run` : lancer un workflow depuis Telegram
* `/workflow_status` : consulter l’état courant
* `/workflow_summary` : afficher ou envoyer le summary
* `/workflow_resume` : reprendre un workflow en `WAITING_HUMAN`

L’orchestration est asynchrone, protégée par `runId`, et l’état est stocké en mémoire par `chatId`.

## Objectif

Améliorer l’expérience utilisateur Telegram sans changer le moteur workflow.

Le but est de rendre les commandes plus lisibles, les messages plus utiles, et le pilotage plus fluide.

## Travail demandé

Analyser l’UX actuelle du bot Telegram workflow et proposer une amélioration progressive.

---

## 1. Inventaire des commandes actuelles

Lister les commandes existantes :

* `/workflow`
* `/workflow_run`
* `/workflow_status`
* `/workflow_summary`
* `/workflow_resume`
* `/workflow_roadmap_load`

Identifier pour chacune :

* rôle
* message actuel
* limites UX
* améliorations possibles

---

## 2. Problèmes UX actuels

Identifier les points faibles possibles :

* commandes trop longues
* messages trop techniques
* manque d’aide contextuelle
* absence de vue synthétique
* absence de rappel des prochaines actions
* difficulté à savoir quoi faire après `WAITING_HUMAN`
* difficulté à savoir quelle roadmap est active
* difficulté à savoir quelle phase/étape est sélectionnée

---

## 3. Proposer une structure de messages standard

Définir un format simple pour :

### Succès

```text
✅ Action effectuée
Détail...
Prochaine action...
```

### Erreur

```text
❌ Action impossible
Raison...
Commande utile...
```

### En cours

```text
⏳ Workflow en cours
Run: ...
Depuis: ...
```

### WAITING_HUMAN

```text
🟠 Action humaine requise
Résumé...
Commandes utiles...
```

---

## 4. Améliorer `/workflow_status`

Proposer un rendu plus utile contenant :

* statut
* projet
* phase
* étape
* roadmap active
* summary disponible ou non
* runId
* startedAt / updatedAt
* prochaine commande recommandée

---

## 5. Améliorer `/workflow`

Proposer un écran d’accueil workflow :

* état rapide
* commandes disponibles
* commande recommandée selon le statut

Exemple :

```text
Workflow assistant ready

Current:
- Project: ...
- Phase: ...
- Étape: ...
- Status: ...

Commands:
- /workflow_run
- /workflow_status
- /workflow_summary
- /workflow_resume
```

Analyser s’il faut ajouter :

## 8. Boutons inline

Analyser si les boutons inline sont utiles dès maintenant.

Exemples :

* après `WAITING_HUMAN` :

  * `Voir summary`
  * `Resume`
  * `Status`
* après `COMPLETED` :

  * `Étape suivante`
  * `Voir summary`

Ne pas implémenter si cela complexifie trop.

### À faire maintenant

Petites améliorations simples et sûres.

### À reporter

Boutons, alias avancés, UX riche, menus.
