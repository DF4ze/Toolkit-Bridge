# PROMPT — Correction Phase 7 Étape 5 — Stabilisation UX Telegram

## Contexte

L’étape 5 a amélioré l’UX Telegram du workflow.

La relecture valide l’architecture générale mais identifie deux corrections nécessaires :

1. le message `Summary too long / Sending complete file` est trompeur si aucun document n’est réellement envoyé ;
2. `/workflow` et `/workflow_status` exposent trop de chemins internes.

## Objectif

Corriger uniquement ces deux points UX, sans changer la logique workflow.

## Corrections à appliquer

### 1. Corriger le message “Summary too long”

Dans :

`WorkflowTelegramSummaryService`

Corriger le cas où le summary est trop long.

Comportement attendu :

* si le document est réellement envoyé :

  * message possible : `Summary too long. Complete file sent.`
* si aucun `TelegramSender` n’est disponible ou si le document n’est pas envoyé :

  * message neutre : `Summary too long. Complete file could not be sent.`
  * ou `Summary too long. Use the summary file directly.`

Le message ne doit jamais prétendre qu’un fichier est envoyé si ce n’est pas vrai.

### 2. Simplifier Roadmap / Summary dans le renderer

Dans :

`WorkflowTelegramMessageRenderer`

Ne plus afficher les chemins complets dans `/workflow` et `/workflow_status`.

Rendu attendu :

Pour roadmap :

```text
Roadmap: loaded
```

ou :

```text
Roadmap: missing
```

Pour summary :

```text
Summary: available
```

ou :

```text
Summary: missing
```

Les chemins complets restent disponibles dans les services/logs/debug si nécessaire, mais pas dans l’UX standard.

### 3. Tests à ajuster

Adapter ou ajouter les tests pour vérifier :

* summary trop long + sender disponible → message cohérent avec envoi réel ;
* summary trop long + sender indisponible → aucun message trompeur ;
* `/workflow` n’affiche pas de chemin roadmap complet ;
* `/workflow_status` n’affiche pas de chemin summary complet ;
* roadmap affiche `loaded/missing` ;
* summary affiche `available/missing`.

## Contraintes strictes

* ne pas modifier runner ;
* ne pas modifier CLI ;
* ne pas modifier orchestration ;
* ne pas modifier le module Telegram ;
* ne pas ajouter de nouvelle commande ;
* ne pas ajouter d’alias ;
* ne pas ajouter de boutons inline ;
* ne pas ajouter de template engine ;
* ne pas changer la logique métier workflow.
