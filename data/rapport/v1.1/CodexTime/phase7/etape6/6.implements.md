# PROMPT — Implémentation Phase 7 Étape 6 — Sécurité minimale Telegram

## Contexte

La sécurité Telegram repose déjà sur :

* le routage par bot avec `@TelegramController(bot = "Cortex")`
* la whitelist du module Telegram via `telegram.bots[].security.allowed-user-ids`

Le module Telegram filtre les utilisateurs avant d’appeler les handlers applicatifs.

Il ne faut donc pas dupliquer la sécurité dans les controllers/services workflow.

## Objectif

Rendre la sécurité minimale explicite et vérifiable, sans ajouter de système complexe.

## Travail demandé

### 1. Documenter la sécurité Telegram workflow

Créer ou compléter une documentation courte dans le dossier de rapport ou dans une doc projet existante.

Elle doit expliquer :

* le bot workflow est rattaché à `Cortex`
* la sécurité repose sur `telegram.bots[].security.allowed-user-ids`
* une whitelist non vide est recommandée en environnement réel
* une whitelist vide peut ouvrir l’accès à tous les utilisateurs selon le comportement du module
* l’usage en groupe est déconseillé si les summaries contiennent des infos sensibles

### 2. Ajouter un warning au démarrage si possible

Ajouter une vérification légère côté application :

* si le bot `Cortex` est configuré
* et si `allowed-user-ids` est vide
* alors logger un warning clair

Exemple :

```text
Telegram workflow bot Cortex has an empty whitelist. Workflow commands may be accessible to any Telegram user reaching this bot.
```

Ne pas bloquer le démarrage.

### 3. Ne pas ajouter de double sécurité

Ne pas modifier les controllers pour refaire un check userId.

Ne pas ajouter de whitelist spécifique workflow.

Ne pas ajouter de rôles.

### 4. Vérifier les messages UX

Ajouter ou conserver des tests garantissant que :

* `/workflow`
* `/workflow_status`

n’exposent pas :

* token
* stacktrace
* chemin absolu

### 5. Contraintes strictes

* ne pas modifier le module Telegram
* ne pas ajouter de DB
* ne pas ajouter de système de rôles
* ne pas bloquer les groupes pour l’instant
* ne pas dupliquer la whitelist
* ne pas modifier runner / CLI / orchestration workflow
