# PROMPT — Analyse Phase 8 CodexCall Étape 2 — Commande Telegram `/workflow_project_set`

## Contexte

Tu interviens sur `Toolkit-Bridge`, sous-système `CodexTime`.

L’étape 1 a ajouté un registre projet persistant permettant de stocker :

`projectName → projectPath`

Les composants suivants existent maintenant :

* `WorkflowProjectEntity`
* `WorkflowProjectRepository`
* `WorkflowProjectRegistryService`
* `WorkflowProjectPathPolicy`
* `WorkflowProjectRegistrationResult`
* `WorkflowProjectLookupResult`

L’étape 1 est validée.

## Objectif de l’étape 2

Analyser comment exposer ce registre via une commande Telegram :

`/workflow_project_set`

Cette commande doit permettre à l’utilisateur de créer ou mettre à jour un mapping projet.

Exemple cible :

`/workflow_project_set name=ToolkitBridge path="D:\Documents\Spring\Mon Projet"`

## Travail demandé

### 1. Analyser l’existant côté controller Telegram

Lire notamment :

* `WorkflowTelegramController`
* les commandes existantes :
  * `/workflow`
  * `/workflow_run`
  * `/workflow_status`
  * `/workflow_summary`
  * `/workflow_resume`
  * `/workflow_roadmap_load`
* les méthodes de parsing actuelles des arguments ;
* `WorkflowTelegramMessageRenderer`.

Identifier :

* où ajouter la commande ;
* comment récupérer les arguments ;
* comment produire un message UX cohérent ;
* comment gérer `chatId` / `userId` si nécessaire.

### 2. Analyser le parsing actuel des arguments

Vérifier comment sont fournis les arguments Telegram :

* `ctx.getArgs()`
* découpage par espaces ;
* format `key=value`.

Identifier la limite actuelle :

* `path=D:\Documents\Spring\Mon Projet` risque d’être coupé à cause des espaces.

### 3. Définir le parsing attendu pour `path`

La commande doit supporter les paths avec espaces dès maintenant.

Formats à supporter :

`path="D:\Documents\Spring\Mon Projet"`

`path='D:\Documents\Spring\Mon Projet'`

`path=D:\Documents\Spring\Toolkit-Bridge`

Règle recommandée :

* continuer à supporter `key=value` ;
* ajouter une extraction spéciale de `path=` capable de récupérer une valeur quoted ;
* si `path=` est le dernier argument, permettre de récupérer le reste de la ligne ;
* supprimer les quotes englobantes si présentes.

Exemples attendus :

`name=ToolkitBridge path="D:\Documents\Spring\Mon Projet"`

doit donner :

* `name = ToolkitBridge`
* `path = D:\Documents\Spring\Mon Projet`

### 4. Définir la commande `/workflow_project_set`

Syntaxe recommandée :

`/workflow_project_set name=<projectName> path="<projectPath>"`

Comportement :

* si projet inconnu : création ;
* si projet existant : update ;
* ne jamais afficher le path absolu dans le message Telegram standard ;
* ne pas charger automatiquement une roadmap ;
* ne pas lancer de workflow ;
* ne pas modifier `/workflow_run` dans cette étape.

### 5. Intégration avec `WorkflowProjectRegistryService`

Analyser comment appeler :

`registerOrUpdate(projectName, projectPath)`

À partir du controller ou d’un service Telegram dédié.

Comparer :

* appeler directement le registry depuis le controller ;
* créer un service Telegram dédié, par exemple `WorkflowTelegramProjectService`.

Recommander l’approche la plus cohérente avec le code existant.

### 6. Messages utilisateur

Définir les messages attendus.

Succès création :

`Action effectuee`
`Detail: Project registered: ToolkitBridge`
`Next: /workflow_run project=ToolkitBridge phase=... etape=...`

Succès update :

`Action effectuee`
`Detail: Project updated: ToolkitBridge`
`Next: /workflow_run project=ToolkitBridge phase=... etape=...`

Erreur nom manquant :

`Action impossible`
`Reason: Missing project name`
`Try: /workflow_project_set name=ToolkitBridge path="<project-path>"`

Erreur path manquant :

`Action impossible`
`Reason: Missing project path`
`Try: /workflow_project_set name=ToolkitBridge path="<project-path>"`

Erreur validation registry :

* reprendre une raison courte depuis `WorkflowProjectRegistrationResult`;
* ne pas exposer stacktrace ;
* ne pas exposer inutilement path absolu.

### 7. Mise à jour de `/workflow`

Analyser s’il faut ajouter `/workflow_project_set` dans la liste des commandes affichées par le dashboard `/workflow`.

Recommandation probable :

* oui, ajouter la commande dans la liste ;
* conserver `/workflow_roadmap_load`.

Ne pas changer le comportement des autres commandes.

### 8. Tests à prévoir

Proposer les tests nécessaires :

* commande succès création ;
* commande succès update ;
* name manquant ;
* path manquant ;
* path avec double quotes ;
* path avec single quotes ;
* path sans espace ;
* path avec espace ;
* registry retourne erreur → message erreur ;
* dashboard `/workflow` contient `/workflow_project_set` ;
* path absolu jamais affiché dans le message succès.

### 9. Risques

Identifier les risques :

* parser trop fragile ;
* gestion des quotes incomplète ;
* path tronqué ;
* path absolu exposé dans Telegram ;
* controller trop chargé ;
* duplication de parsing entre commandes ;
* impact involontaire sur `/workflow_roadmap_load` ou `/workflow_run`.

### 10. Plan d’implémentation

Proposer un plan clair en 5 à 8 étapes maximum.
