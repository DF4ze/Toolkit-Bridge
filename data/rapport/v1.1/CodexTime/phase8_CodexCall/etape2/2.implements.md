# PROMPT — Implémentation Phase 8 CodexCall Étape 2 — Commande Telegram `/workflow_project_set`

## Contexte

Tu interviens sur `Toolkit-Bridge`, sous-système `CodexTime`.

L’étape 1 a ajouté un registre projet persistant :

* `WorkflowProjectEntity`
* `WorkflowProjectRepository`
* `WorkflowProjectRegistryService`
* `WorkflowProjectPathPolicy`
* `WorkflowProjectRegistrationResult`
* `WorkflowProjectLookupResult`

L’analyse de l’étape 2 est disponible ici :

`data/rapport/v1.1/CodexTime/phase8_CodexCall/etape2/result_2_analysis.md`

Elle recommande d’ajouter une commande Telegram :

```text
/workflow_project_set
```

pour créer ou mettre à jour un mapping :

```text
projectName → projectPath
```

## Objectif

Ajouter la commande Telegram :

```text
/workflow_project_set name=ToolkitBridge path="D:\Documents\Spring\Mon Projet"
```

Cette commande doit :

* créer un projet si le nom n’existe pas ;
* mettre à jour le path si le projet existe ;
* gérer les chemins avec espaces via quotes ;
* ne jamais afficher le path absolu dans les messages Telegram ;
* ne pas lancer de workflow ;
* ne pas modifier `/workflow_run` ;
* ne pas modifier `/workflow_resume`.

## Décisions retenues

### Commande

Utiliser exactement :

```text
/workflow_project_set
```

### Arguments obligatoires

```text
name=<projectName>
path=<projectPath>
```

### Formats de path à supporter

```text
path=D:\Documents\Spring\Toolkit-Bridge
path="D:\Documents\Spring\Mon Projet"
path='D:\Documents\Spring\Mon Projet'
```

Si le path contient des espaces, il doit être quoté.

Ne pas tenter de supporter les paths avec espaces non quotés.

### UX

Utiliser `WorkflowTelegramMessageRenderer`.

Succès création :

```text
Action effectuee
Detail: Project registered: ToolkitBridge
Next: /workflow_run project=ToolkitBridge phase=... etape=...
```

Succès update :

```text
Action effectuee
Detail: Project updated: ToolkitBridge
Next: /workflow_run project=ToolkitBridge phase=... etape=...
```

Erreur :

```text
Action impossible
Reason: ...
Try: /workflow_project_set name=ToolkitBridge path="<project-path>"
```

## Travail demandé

### 1. Créer un service Telegram dédié

Créer :

```text
WorkflowTelegramProjectService
```

Package cohérent avec les autres services Telegram workflow.

Responsabilités :

* appeler `WorkflowProjectRegistryService.registerOrUpdate(...)` ;
* convertir le résultat en message Telegram via `WorkflowTelegramMessageRenderer` ;
* éviter toute fuite de path absolu dans les messages.

Le service ne doit pas lancer de workflow.

### 2. Ajouter la commande dans le controller

Dans :

```text
WorkflowTelegramController
```

Ajouter :

```java
@Command("/workflow_project_set")
```

Le handler doit rester fin :

* récupérer les arguments ;
* extraire `name` ;
* extraire `path` ;
* déléguer à `WorkflowTelegramProjectService` ;
* retourner la string utilisateur.

### 3. Parsing de `name`

Utiliser le parsing `key=value` classique.

Règles :

* `name` obligatoire ;
* `name=` vide → erreur `Missing project name`.

### 4. Parsing de `path` avec quotes

Ajouter une méthode localisée et testable pour extraire :

```text
path=...
```

depuis `ctx.getArgs()`.

Règles :

* `path` obligatoire ;
* `path=` vide → erreur `Missing project path`;
* si la valeur commence par `"` :
  * concaténer les tokens suivants jusqu’à une valeur terminant par `"`;
  * retirer les quotes englobantes ;
* si la valeur commence par `'` :
  * concaténer les tokens suivants jusqu’à une valeur terminant par `'`;
  * retirer les quotes englobantes ;
* si quote ouverte mais non fermée :
  * erreur `Invalid quoted path (missing closing quote)`;
* si pas de quote :
  * prendre uniquement le token courant.

### 5. Gestion des erreurs registry

Si `WorkflowProjectRegistryService` retourne un échec :

* retourner un message d’erreur standard ;
* utiliser une raison courte ;
* ne pas afficher le path absolu.

Si la raison retournée contient un path, la masquer ou la remplacer par une raison générique.

### 6. Ajouter la commande au dashboard `/workflow`

Dans le renderer du dashboard, ajouter :

```text
- /workflow_project_set
```

Ne pas modifier la logique de recommandation `Next`.

### 7. Tests attendus

Ajouter ou adapter les tests.

#### Parsing

* path sans quotes ;
* path avec double quotes et espaces ;
* path avec single quotes et espaces ;
* quote non fermée ;
* path manquant ;
* name manquant.

#### Service / commande

* création projet → message `Project registered`;
* update projet → message `Project updated`;
* registry failure → message `Action impossible`;
* aucun message succès ne contient `D:\`, `C:\`, `/home/`.

#### Dashboard

* `/workflow` contient `/workflow_project_set`.
