# PROMPT — Implémentation Phase 9 Logging Étape 3 — Logs process, validation bas niveau et registre projet

## Contexte

Tu interviens sur `Toolkit-Bridge`, sous-système `CodexTime`.

La Phase 9 vise à ajouter une journalisation intelligente, sobre et utile.

Les étapes précédentes ont ajouté ou demandé les logs sur :

* couche Telegram et orchestration ;
* runner ;
* orchestrator ;
* steps métier Codex / Maven.

Cette étape 3 concerne les couches bas niveau :

* client Codex CLI ;
* validation process/Maven ;
* registre projet.

## Objectif

Ajouter des logs permettant de diagnostiquer :

* le lancement du process Codex CLI ;
* les timeouts Codex ;
* les erreurs I/O du process Codex ;
* les validations process locales ;
* les timeouts de validation ;
* les projets créés / mis à jour ;
* les refus de project registry.

Ne pas modifier le comportement métier.

## Classes concernées

Instrumenter uniquement si présentes :

* `CodexWorkflowClient`
* `WorkflowValidationService`
* `WorkflowProjectRegistryService`

## Exigence technique

Utiliser Lombok :

```java
@Slf4j
```

Ajouter l'annotation sur les classes qui n'ont pas encore de logger.

Ne pas ajouter de framework de logging.

## Règles de logs

### INFO

Pour les événements bas niveau importants mais peu fréquents :

* démarrage du process Codex ;
* projet créé ;
* projet mis à jour.

### DEBUG

Pour les détails utiles au diagnostic :

* commande construite sans prompt ;
* présence ou absence de working directory ;
* durée ;
* exit code ;
* status validation ;
* taille stdout/stderr ;
* commande Maven/process si elle ne contient pas de secret.

### WARN

Pour les anomalies récupérables :

* timeout Codex ;
* timeout validation process ;
* projet introuvable si cela se produit dans un contexte lookup ;
* path projet refusé ;
* nom projet invalide ;
* path invalide.

### ERROR

Pour les erreurs techniques réelles :

* process Codex impossible à démarrer ;
* erreur I/O process ;
* interruption ;
* validation process impossible à démarrer ;
* exception technique non récupérable.

## Confidentialité stricte

Ne jamais logger :

* prompt Codex ;
* contenu de fichier ;
* rapport complet ;
* summary complet ;
* stdout/stderr complets ;
* token ;
* clé API ;
* secret ;
* `projectPath` en `INFO`.

Autorisé :

* `durationMs`;
* `exitCode`;
* `status`;
* `stdoutLen`;
* `stderrLen`;
* `workingDirectory=set|none` en INFO ;
* commande sans prompt en DEBUG ;
* path en DEBUG uniquement si vraiment utile.

## Travail demandé

### 1. `CodexWorkflowClient`

La classe possède peut-être déjà `@Slf4j`. La conserver si elle existe.

Ajouter ou enrichir les logs sans changer le comportement.

#### INFO — démarrage process

Avant `processBuilder.start()` :

```java
log.info("Codex CLI process starting: workingDirectory={}",
        request.workingDirectory() != null ? "set" : "none");
```

Ne pas logger le path absolu en INFO.

#### DEBUG — commande et résultat

Ajouter ou enrichir :

```java
log.debug("Codex CLI command built: command={}", safeCommand);
```

où `safeCommand` ne contient jamais le prompt.

À la fin :

```java
log.debug("Codex CLI execution finished: exitCode={}, durationMs={}, stdoutLen={}, stderrLen={}",
        exitCode, durationMs, stdout.length(), stderr.length());
```

#### WARN — timeout

Ajouter un log `WARN` lorsqu'un timeout se produit :

```java
log.warn("Codex CLI process timed out: durationMs={}", durationMs);
```

#### ERROR — erreurs process

Conserver ou ajouter des logs `ERROR` pour :

* `IOException`;
* `InterruptedException`;
* erreur I/O lors de l'écriture stdin si présente.

Exemple :

```java
log.error("Codex CLI process failed to start", e);
```

ou :

```java
log.error("Codex CLI process interrupted", e);
```

#### Contraintes spécifiques

* Ne jamais logger `request.prompt()`.
* Ne jamais logger stdout/stderr complets.
* Ne pas modifier la commande Codex.
* Ne pas ajouter `--json`.
* Ne pas ajouter `--output-last-message`.
* Ne pas ajouter `--sandbox`.

### 2. `WorkflowValidationService`

Ajouter `@Slf4j` si absent.

#### DEBUG — démarrage et résultat

Au démarrage de la validation process :

```java
log.debug("Process validation starting: command={}, timeoutSeconds={}",
        commandString, timeoutSeconds);
```

À la fin :

```java
log.debug("Process validation finished: status={}, exitCode={}, durationMs={}, stdoutLen={}, stderrLen={}",
        result.status(), result.exitCode(), result.durationMs(),
        result.stdout().length(), result.stderr().length());
```

#### WARN — timeout

```java
log.warn("Process validation timed out: command={}, durationMs={}",
        commandString, durationMs);
```

#### ERROR — erreurs système

```java
log.error("Process validation failed to start: command={}", commandString, e);
```

```java
log.error("Process validation interrupted: command={}", commandString, e);
```

#### Contraintes spécifiques

* `commandString` est acceptable si elle ne contient pas de secret.
* Ne jamais logger stdout/stderr complets.
* Ne pas modifier la logique de validation.
* Ne pas modifier les statuts retournés.

### 3. `WorkflowProjectRegistryService`

Ajouter `@Slf4j` si absent.

#### INFO — succès

Lors d'une création :

```java
log.info("Workflow project registered: projectName={}, projectKey={}",
        projectName, projectKey);
```

Lors d'une mise à jour :

```java
log.info("Workflow project updated: projectName={}, projectKey={}",
        projectName, projectKey);
```

Ne pas logger `projectPath`.

#### WARN — refus

Ajouter des logs `WARN` pour les refus importants :

* nom invalide ;
* path invalide ;
* path dangereux ;
* path inexistant ;
* path non dossier ;
* path non lisible ;
* path non writable.

Exemples :

```java
log.warn("Workflow project registration rejected: reason={}", reason);
```

ou, si disponible :

```java
log.warn("Workflow project registration rejected: projectName={}, reason={}",
        safeProjectName, reason);
```

Ne jamais inclure le path brut ou normalisé dans `reason` si celui-ci contient un path.

#### DEBUG — lookup

Pour lookup :

```java
log.debug("Workflow project lookup: projectKey={}, found={}", projectKey, found);
```

Ne pas logger `projectPath`.

#### Contraintes spécifiques

* Ne pas modifier les messages utilisateur retournés.
* Ne pas modifier la validation.
* Ne pas modifier le modèle DB.
* Ne pas logger le path absolu en INFO.
