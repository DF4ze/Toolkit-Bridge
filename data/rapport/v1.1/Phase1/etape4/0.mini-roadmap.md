# Mini-roadmap — v1.1 / Phase 1 / Étape 4 (Sécurité admin)

## 🎯 Objectif global

Passer d’une sécurité admin MVP à une sécurité **déjà saine**, sans sur-architecture.

---

## 🔹 Lot 1 — Suppression des fuites de secrets

**Priorité : CRITIQUE**

### Objectif

Éliminer toute exposition de secrets dans les logs.

### Périmètre

* `AdminTokenService` (master token)
* `AgentAccountInitializer` (API keys)
* scan rapide des logs sensibles

### Pourquoi en premier

* risque immédiat élevé
* correction simple et sans impact

---

## 🔹 Lot 2 — Rate limiting login admin

**Priorité : TRÈS ÉLEVÉE**

### Objectif

Empêcher le brute force sur `/login`.

### Périmètre

* `LoginController`
* ou filtre dédié
* stockage simple en mémoire (IP → compteur)

### Contraintes

* solution simple
* pas de dépendance externe

---

## 🔹 Lot 3 — Durcissement session & cookies

**Priorité : ÉLEVÉE**

### Objectif

Sécuriser la session admin côté navigateur.

### Périmètre

* rotation de session ID au login
* timeout session explicite
* flags cookie :

    * HttpOnly
    * Secure
    * SameSite

### Risque

* peut impacter la navigation → à tester

---

## 🔹 Lot 4 — Protection CSRF minimale

**Priorité : ÉLEVÉE**

### Objectif

Empêcher les actions admin non intentionnelles.

### Périmètre

* formulaires POST (`/login`, `/logout`, `/admin/**`)
* endpoints admin mutatifs

### Choix à faire

* implémentation custom légère
* ou introduction minimale de Spring Security

---

## 🔹 Lot 5 — Gouvernance du token maître

**Priorité : MOYENNE**

### Objectif

Rendre le token exploitable en production.

### Périmètre

* rotation simple (manuel assisté)
* documentation du cycle de vie
* invalidation claire

---

## 🔹 Lot 6 — Préparation secret manager

**Priorité : MOYENNE**

### Objectif

Éviter un verrou architectural.

### Périmètre

* abstraction simple pour source du token
* compatibilité avec fichier actuel

---

## 🔹 Lot 7 — Tests d’intégration sécurité

**Priorité : IMPORTANTE**

### Objectif

Éviter les régressions.

### Périmètre

* login success/fail
* rate limit
* session/cookie
* CSRF
* non-fuite des secrets

---

## ⚠️ Ordre IMPÉRATIF

1. Lot 1 — Secrets (immédiat)
2. Lot 2 — Rate limiting
3. Lot 3 — Session/cookies
4. Lot 4 — CSRF
5. Lot 5 — Token lifecycle
6. Lot 6 — Secret manager prep
7. Lot 7 — Tests

---

## 🧠 Stratégie globale

* rester **simple et incrémental**
* ne jamais casser le flow admin
* ne pas introduire de complexité prématurée
* sécuriser d’abord → structurer ensuite
